问题 1：MetaMask 单地址能否完成所有操作？

不能完全做到。 当前操作分两类：                                                          
┌───────────────────────┬──────────┬──────────────┬────────────────────────────────────┐
│       操作类型        │ 签名方式 │  走哪个服务  │        MetaMask 能直接做？         │
├───────────────────────┼──────────┼──────────────┼────────────────────────────────────┤
│ 下单 (Place Order)    │ EIP-712  │ Exchange API │ 可以                               │
├───────────────────────┼──────────┼──────────────┼────────────────────────────────────┤
│ 撤单 (Cancel)         │ EIP-712  │ Exchange API │ 可以                               │
├───────────────────────┼──────────┼──────────────┼────────────────────────────────────┤
│ 平仓 (Close Position) │ EIP-712  │ Exchange API │ 可以                               │
├───────────────────────┼──────────┼──────────────┼────────────────────────────────────┤
│ 充值 (Deposit)        │ 链上交易 │ Gateway      │ 不能 — 需要链上 MintCoin + Deposit │
├───────────────────────┼──────────┼──────────────┼────────────────────────────────────┤
│ 提现 (Withdraw)       │ 链上交易 │ Gateway      │ 不能 — 需要链上交易                │
├───────────────────────┼──────────┼──────────────┼────────────────────────────────────┤
│ Faucet / 创建市场     │ 链上交易 │ Gateway      │ 不能 — 管理员操作                  │
└───────────────────────┴──────────┴──────────────┴────────────────────────────────────┘
核心瓶颈在 Deposit/Withdraw：这两个操作需要构建链上交易并提交到 Sui 网络，当前只有
Gateway 能做。

问题 2：Gateway 是否包含核心代码？

Gateway 不包含核心逻辑，设计是合理的。

- Gateway (tx-gateway) = 开发/测试便利层，用 DexClient 封装链上交易
- Exchange API (dex-api) = 生产级交易接口，EIP-712 签名验证 + 免 gas 交易提交
- Sui 执行层 (sui-execution/src/dex/) = 真正的核心引擎（撮合、风控）

交易的核心流程已经在 Exchange API 中完整实现：
MetaMask EIP-712 签名 → API 验签 → 构建 DEX 交易 → index-0 代付 gas → 提交 Sui

要让 MetaMask 完成所有操作，需要什么？

需要在 Exchange API 增加 Deposit/Withdraw 的 EIP-712 端点：

1. Deposit：用户用 MetaMask 签名 {action: "deposit", amount: 1000} → API 构建 MintCoin +
   Deposit 交易 → 提交
2. Withdraw：用户签名 {action: "withdraw", amount: 500} → API 构建 Withdraw 交易 → 提交

这样 MetaMask 用户就能通过 Exchange API 完成全部操作，完全不需要 Gateway。

结论

- Gateway 不是核心，是测试工具 — 设计没问题
- 交易操作（下单/撤单/平仓）已经可以纯 MetaMask + Exchange API 完成
- 要彻底去掉 Gateway 依赖，只需把 Deposit/Withdraw 加上 EIP-712 签名支持到 Exchange API
