# Listing 模块产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品定位

Listing (市场上市) 模块是 Hermes DEX 的**无需许可市场创建系统**,允许任何人通过简单流程创建新的永续合约市场,实现真正的去中心化市场上市。

### 1.2 核心价值

**对项目方**:
- 无需审批,自由创建市场
- 低门槛,自动化配置
- 快速上市,抢占市场先机

**对交易者**:
- 更多交易品种选择
- 更快获得新项目交易机会
- 去中心化,抗审查

**对系统**:
- 自动化流程,减少人工干预
- 标准化参数,降低风险
- 初始流动性保证,提高成功率

### 1.3 目标用户

- **新项目方**: 希望为自己的代币创建永续合约市场
- **社区成员**: 为热门代币创建市场,获得早期优势
- **做市商**: 为新市场提供流动性,赚取价差

## 2. 功能需求

### FR-1: 一键市场创建

**需求描述**: 用户可以通过单个交易创建完整的永续合约市场,包括价格市场、永续合约和交易对配置。

#### FR-1.1: 市场创建流程

**功能点**:
- 用户提交单个消息,创建完整市场
- 系统自动配置价格市场 (Market)
- 系统自动创建永续合约 (Perpetual)
- 系统自动创建交易对 (CLOBPair)
- 市场立即可用于交易

**业务规则**:
- 用户必须提供 Ticker (交易对名称,如 "DOGE-USD")
- 系统自动分配市场 ID、合约 ID、交易对 ID
- 用户必须存入最低 Vault 存款 (例如 10,000 USDC)
- 市场总数不能超过硬上限 (例如 1,000 个市场)

**验收标准**:
- 用户可以成功创建新市场
- 创建的市场包含完整的 Market、Perpetual、CLOBPair
- 市场创建后立即可以开始交易
- 存款不足时创建失败

**用户场景**:

场景 1: 项目方为 DOGE 创建市场
- 参与者: DOGE 项目方 Alice
- 前置条件:
  - Alice 有 10,000 USDC
  - DOGE-USD 市场尚未存在
  - 系统市场总数 < 硬上限
- 流程:
  1. Alice 提交创建市场消息:
     - Ticker: "DOGE-USD"
     - VaultDeposit: 10,000 USDC
  2. 系统验证:
     - ✅ DOGE-USD 市场不存在
     - ✅ Alice 有 10,000 USDC
     - ✅ 市场总数 < 硬上限
  3. 系统创建市场:
     - 创建 Market (ID = 101, Pair = "DOGE/USD")
     - 创建 Perpetual (ID = 101, Ticker = "DOGE-USD", MarketId = 101)
     - 创建 CLOBPair (ID = 101, PerpetualId = 101)
  4. 系统将 Alice 的 10,000 USDC 存入 Megavault
  5. 市场创建成功,DOGE-USD 可以开始交易
- 后置条件: DOGE-USD 市场可用,Alice 持有 Megavault 份额

#### FR-1.2: 市场硬上限保护

**功能点**:
- 系统设置市场总数硬上限
- 超过硬上限时拒绝新市场创建
- 防止无限制创建市场

**业务规则**:
- 硬上限通过治理设置 (例如 1,000 个市场)
- 硬上限包括所有状态的市场 (活跃、暂停等)
- 只有删除旧市场才能释放配额

**验证逻辑**:
```
拒绝创建市场 if: 当前市场数量 >= 硬上限
```

**重要说明**:
- 使用 `>=` 而非 `>` 进行验证,确保硬上限精确控制
- 当市场数量等于硬上限时,已无法创建新市场
- 例如: 硬上限 = 1,000,当市场数量达到 1,000 时,拒绝第 1,001 个市场创建

**验收标准**:
- 超过硬上限时创建失败
- 达到硬上限时也拒绝创建
- 错误消息清晰说明原因
- 硬上限可以通过治理调整

**用户场景**:

场景 2: 市场硬上限保护
- 参与者: 用户 Bob
- 前置条件: 系统已有 1,000 个市场 (达到硬上限)
- 流程:
  1. Bob 尝试创建 PEPE-USD 市场
  2. 系统验证市场总数 = 1,000 (达到硬上限)
  3. 系统拒绝创建请求
  4. 返回错误: "市场总数已达上限 (1,000),无法创建新市场"
- 后置条件: 创建失败,Bob 的 USDC 未被扣除

### FR-2: 默认参数自动配置

**需求描述**: 系统根据项目市值和风险等级自动选择合适的流动性层级和默认参数,简化用户操作。

#### FR-2.1: 流动性层级自动选择

**功能点**:
- 系统提供多个预设流动性层级 (Large-Cap, Mid-Cap, Small-Cap)
- 用户创建市场时可以指定流动性层级
- 如果未指定,系统根据市值自动选择

**流动性层级配置**:

| 层级          | 适用项目              | 初始保证金率  | 最大杠杆  |
|--------------|---------------------|-------------|----------|
| Large-Cap    | 市值 > 100 亿美元     | 5%          | 20x      |
| Mid-Cap      | 市值 10 亿 - 100 亿   | 10%         | 10x      |
| Small-Cap    | 市值 < 10 亿          | 20%         | 5x       |
| Meme         | 高波动性代币          | 50%         | 2x       |

**业务规则**:
- 用户可以手动选择流动性层级
- 如果未指定,系统默认使用 Mid-Cap
- 流动性层级决定保证金要求、最大杠杆等参数

**验收标准**:
- 用户可以选择流动性层级
- 默认层级正确应用
- 不同层级的保证金要求不同

**用户场景**:

场景 3: 选择流动性层级
- 参与者: 项目方 Carol (SHIB 代币)
- 前置条件: SHIB 市值约 50 亿美元
- 流程:
  1. Carol 创建 SHIB-USD 市场
  2. Carol 选择流动性层级 = Mid-Cap
  3. 系统应用 Mid-Cap 参数:
     - 初始保证金率 = 10%
     - 最大杠杆 = 10x
     - OIMF 参数: LowerCap = 1,000 万 USDC, UpperCap = 1 亿 USDC
  4. 市场创建成功,使用 Mid-Cap 参数
- 后置条件: SHIB-USD 市场使用 Mid-Cap 风险参数

#### FR-2.2: 默认参数配置

**功能点**:
- 系统为每个流动性层级预设默认参数
- 包括价格精度、最小订单数量、价差等
- 用户无需手动配置复杂参数

**默认参数示例 (Large-Cap)**:

| 参数              | 默认值                | 说明                          |
|------------------|---------------------|------------------------------|
| 原子精度          | -10                 | 10^-10 精度                   |
| 最小订单数量      | 0.001               | 最小 0.001 个单位             |
| 价格步长          | 1 USDC              | 价格最小变动单位              |
| 默认资金费率      | 0                   | 8 小时 0% (动态调整)          |
| OIMF 下限         | 10,000 万 USDC      | 未平仓合约量下限              |
| OIMF 上限         | 100,000 万 USDC     | 未平仓合约量上限              |

**业务规则**:
- 默认参数适用于大部分项目
- 创建后可以通过治理调整参数
- 参数设计平衡风险和用户体验

**验收标准**:
- 默认参数正确应用
- 参数适合目标市场
- 用户无需手动配置

### FR-3: Vault 存款门槛

**需求描述**: 用户创建市场时必须向 Megavault 存入最低金额,作为初始流动性,防止垃圾市场。

#### FR-3.1: 存款要求

**功能点**:
- 创建市场时必须存入最低 USDC
- 存款金额通过治理配置 (例如 10,000 USDC)
- 存款作为 Vault 流动性,可以提款

**计算公式**:

**存款门槛验证**:

数学表达式:
```
创建市场 if: DepositAmount >= MinVaultDeposit
```

变量说明:
- **DepositAmount**: 用户存入的 USDC 数量
- **MinVaultDeposit**: 最低 Vault 存款要求 (USDC),通过治理配置

计算示例:
- 假设 MinVaultDeposit = 10,000 USDC
- 假设用户存入 15,000 USDC
- 15,000 >= 10,000 ✅ 通过验证,允许创建市场

计算示例 (不满足):
- 假设 MinVaultDeposit = 10,000 USDC
- 假设用户存入 5,000 USDC
- 5,000 < 10,000 ❌ 验证失败,拒绝创建

业务解释:
- 存款门槛防止用户随意创建垃圾市场
- 存款提供初始流动性,提高市场成功率
- 存款进入 Megavault,用户可以后续提款

**业务规则**:
- 存款金额不能低于最低要求
- 存款立即转入 Megavault,铸造份额给用户
- 用户可以随时提款 (遵守 Vault 提款规则)

**验收标准**:
- 存款不足时创建失败
- 存款成功进入 Vault
- 用户获得对应份额

**用户场景**:

场景 4: Vault 存款门槛
- 参与者: 用户 Dave
- 前置条件: Dave 有 5,000 USDC,MinVaultDeposit = 10,000 USDC
- 流程:
  1. Dave 尝试创建 XYZ-USD 市场,存入 5,000 USDC
  2. 系统验证存款金额: 5,000 < 10,000
  3. 系统拒绝创建请求
  4. 返回错误: "Vault 存款不足,至少需要 10,000 USDC"
  5. Dave 追加 5,000 USDC,总共 10,000 USDC
  6. 再次提交创建请求
  7. 系统验证通过,创建市场成功
  8. Dave 的 10,000 USDC 进入 Megavault
- 后置条件: 市场创建成功,Dave 持有 Vault 份额

#### FR-3.2: 双重 Vault 存款机制

**功能点**:
- 创建市场时,存款可能需要同时存入两个 Vault
- 新市场 Vault 存款 + 主 Vault (Megavault) 存款
- 总存款 = 新 Vault 存款 + 主 Vault 存款

**计算公式**:

**总存款计算**:

数学表达式:
```
TotalDeposit = NewVaultDepositAmount + MainVaultDepositAmount
创建市场 if: TotalDeposit >= MinVaultDeposit
```

变量说明:
- **NewVaultDepositAmount**: 存入新市场专属 Vault 的金额 (USDC)
- **MainVaultDepositAmount**: 存入 Megavault (主 Vault) 的金额 (USDC)
- **TotalDeposit**: 总存款金额 (USDC)
- **MinVaultDeposit**: 最低总存款要求 (USDC)

**默认配置** (当前系统):
```
NewVaultDepositAmount = 10,000 USDC (默认)
MainVaultDepositAmount = 0 USDC (默认)
TotalDeposit = 10,000 USDC
```

计算示例 (自定义配置):
- 假设用户设置:
  - NewVaultDepositAmount = 7,000 USDC
  - MainVaultDepositAmount = 5,000 USDC
- TotalDeposit = 7,000 + 5,000 = **12,000 USDC**
- MinVaultDeposit = 10,000 USDC
- 12,000 >= 10,000 ✅ 通过验证

业务解释:
- **新 Vault 存款**: 为新市场创建专属流动性池,仅做市该市场
- **主 Vault 存款**: 进入 Megavault,参与所有市场做市
- **双重存款**: 提供更大流动性,提高新市场成功率
- **灵活配置**: 用户可以选择资金分配比例

**业务规则**:
- 两个存款的总和必须满足最低要求
- 新 Vault 存款用于新市场专属流动性
- 主 Vault 存款参与全局做市,收益分散
- 两笔存款都会铸造对应份额给用户

**验收标准**:
- 总存款计算正确
- 两笔存款正确进入各自 Vault
- 用户获得两种 Vault 份额

**用户场景**:

场景 4.1: 使用双重存款创建市场
- 参与者: 项目方 Emily
- 前置条件:
  - Emily 有 20,000 USDC
  - MinVaultDeposit = 10,000 USDC
- 流程:
  1. Emily 创建 TOKEN-USD 市场,设置双重存款:
     - NewVaultDepositAmount = 15,000 USDC (为新市场提供专属流动性)
     - MainVaultDepositAmount = 5,000 USDC (参与 Megavault 全局做市)
  2. 系统验证总存款: 15,000 + 5,000 = 20,000 >= 10,000 ✅
  3. 系统执行存款:
     - 15,000 USDC → TOKEN-USD 专属 Vault,铸造 15,000 份额
     - 5,000 USDC → Megavault,铸造对应份额
  4. 市场创建成功
  5. TOKEN-USD 市场开始交易,使用专属流动性做市
  6. Emily 同时持有两种 Vault 份额:
     - TOKEN-USD Vault 份额: 做市 TOKEN-USD,收益集中
     - Megavault 份额: 做市所有市场,收益分散
- 后置条件:
  - 市场创建成功
  - Emily 持有两种 Vault 份额
  - TOKEN-USD 有专属流动性 + Megavault 全局流动性

#### FR-3.3: Vault 份额锁定机制

**功能点**:
- 创建市场时铸造的 Vault 份额会被锁定一段时间
- 锁定期间不能提款,防止快进快出
- 锁定期结束后可以正常提款

**计算公式**:

**锁定期计算**:

数学表达式:
```
UnlockBlockHeight = CurrentBlockHeight + NumBlocksToLockShares
```

变量说明:
- **UnlockBlockHeight**: 解锁区块高度
- **CurrentBlockHeight**: 当前区块高度
- **NumBlocksToLockShares**: 锁定区块数 (通过治理配置)

**默认配置**:
```
NumBlocksToLockShares = 2,592,000 区块
区块时间 ≈ 1 秒
锁定时长 ≈ 2,592,000 秒 ≈ 30 天
```

计算示例:
- 假设当前区块高度 = 1,000,000
- 假设 NumBlocksToLockShares = 2,592,000
- 解锁区块高度 = 1,000,000 + 2,592,000 = **3,592,000**
- 解锁时间 ≈ 当前时间 + 30 天

业务解释:
- **防止快进快出**: 锁定机制防止用户创建市场后立即提款,确保流动性稳定
- **激励长期参与**: 鼓励用户长期持有份额,参与市场做市
- **保护市场质量**: 垃圾市场创建者无法快速撤资

**业务规则**:
- 创建市场时铸造的份额自动锁定
- 锁定期由治理参数控制 (默认 30 天)
- 锁定期间份额仍然参与做市,产生收益
- 锁定期结束后可以正常提款
- 后续追加存款的份额不受此限制 (仅创建时锁定)

**验收标准**:
- 创建市场时份额正确锁定
- 锁定期间提款请求被拒绝
- 锁定期结束后可以提款
- 锁定期间做市收益正常计入

**用户场景**:

场景 4.2: 份额锁定与解锁
- 参与者: 用户 Frank
- 前置条件:
  - Frank 有 10,000 USDC
  - NumBlocksToLockShares = 2,592,000 区块 (30 天)
  - 当前区块高度 = 1,000,000
- 流程:
  1. Frank 创建 ABC-USD 市场,存入 10,000 USDC
  2. 系统铸造 10,000 Vault 份额给 Frank
  3. 系统锁定份额:
     - 锁定解锁高度 = 1,000,000 + 2,592,000 = 3,592,000
     - 锁定时长 ≈ 30 天
  4. **Day 10**: Frank 尝试提款,提取 5,000 份额
     - 系统检查: 当前高度 1,864,000 < 解锁高度 3,592,000
     - 系统拒绝: "份额仍在锁定期,解锁时间约 20 天后"
  5. **Day 30**: 区块高度达到 3,592,000
     - 份额自动解锁
  6. **Day 31**: Frank 再次提款,提取 5,000 份额
     - 系统检查: 当前高度 3,678,400 > 解锁高度 3,592,000 ✅
     - 系统执行提款,Frank 获得对应 USDC
  7. Frank 保留 5,000 份额继续做市
- 后置条件:
  - Frank 成功提款 5,000 份额
  - 剩余 5,000 份额继续参与做市

**业务价值**:
- 30 天锁定期确保流动性稳定
- 防止垃圾市场创建者快速撤资
- 保护系统和其他参与者利益

#### FR-3.4: Vault 自动激活做市

**功能点**:
- 创建市场时,新市场的 Vault 自动设置为"做市状态"
- 无需手动激活,立即开始为新市场提供流动性
- 提高新市场成功率

**业务规则**:

**Vault 状态自动设置**:

创建市场时:
```
新市场 Vault 状态 = VAULT_STATUS_QUOTING (做市中)
```

状态说明:
- **VAULT_STATUS_QUOTING**: Vault 正在为市场提供流动性,自动挂单做市
- **VAULT_STATUS_STAND_BY**: Vault 暂停做市,不自动挂单
- **VAULT_STATUS_DEACTIVATED**: Vault 停用,不参与市场

**默认行为**:
- 创建市场时,系统自动将新市场 Vault 设置为 `VAULT_STATUS_QUOTING`
- Vault 立即开始根据预设参数自动挂单
- 无需用户手动激活,降低操作门槛

**验收标准**:
- 创建市场后,Vault 状态为 QUOTING
- Vault 立即开始做市,挂单可见
- 新市场有初始流动性

**用户场景**:

场景 4.3: Vault 自动激活做市
- 参与者: 项目方 Grace
- 前置条件:
  - Grace 创建 TOKEN-USD 市场
  - 存入 10,000 USDC
- 流程:
  1. Grace 提交创建市场交易
  2. 系统创建市场成功
  3. 系统自动设置:
     - TOKEN-USD Vault 状态 = VAULT_STATUS_QUOTING
  4. **立即生效**: Vault 开始自动做市
     - 根据预设参数在订单簿挂买单和卖单
     - 提供初始流动性,价差 ±0.5%
  5. 其他交易者看到订单簿有流动性,开始交易
  6. Vault 通过做市赚取价差收益
- 后置条件:
  - 市场创建即有流动性
  - 降低用户操作复杂度
  - 提高市场成功率

## 3. 非功能需求

### NFR-1: 性能要求

**市场创建性能**:
- 市场创建延迟 < 区块时间
- 创建成功后立即可用
- 支持每天至少创建 10 个新市场

**查询性能**:
- 市场列表查询延迟 < 200ms
- 市场详情查询延迟 < 100ms

**验收标准**:
- 性能测试达到目标
- 创建流程稳定可靠

### NFR-2: 安全性要求

**防垃圾市场**:
- Vault 存款门槛有效防止垃圾市场
- 市场硬上限防止无限制创建
- 参数合理,降低风险

**资金安全**:
- Vault 存款安全存储
- 用户可以提款
- 存款转账原子性

**验收标准**:
- 垃圾市场创建失败
- 用户资金安全
- 无资金丢失风险

### NFR-3: 可扩展性要求

**参数可配置**:
- 流动性层级可以通过治理添加
- 默认参数可以调整
- Vault 存款门槛可以修改

**市场容量**:
- 支持至少 1,000 个市场
- 新市场不影响现有市场性能

**验收标准**:
- 参数调整流程顺畅
- 扩展性测试通过

## 4. 用户场景

### 场景 5: 社区为热门 Meme 币创建市场

**参与者**: 社区成员 Eve

**前置条件**:
- 新的 Meme 币 PEPE 在社交媒体爆火
- PEPE-USD 市场尚未存在
- Eve 有 10,000 USDC

**流程**:
1. Eve 发现 PEPE 没有永续合约市场
2. Eve 提交创建市场消息:
   - Ticker: "PEPE-USD"
   - LiquidityTier: Meme (高波动性)
   - VaultDeposit: 10,000 USDC
3. 系统创建市场:
   - 应用 Meme 层级参数: 初始保证金率 50%, 最大杠杆 2x
   - 存入 10,000 USDC 到 Megavault
4. 市场创建成功,PEPE-USD 可以交易
5. Eve 作为第一个流动性提供者,获得 Vault 份额
6. 其他交易者开始在 PEPE-USD 市场交易
7. Eve 的 Vault 份额随市场交易盈亏变化

**后置条件**: PEPE-USD 市场上线,Eve 作为早期流动性提供者参与市场

**业务价值**:
- 去中心化市场创建,社区驱动
- 快速响应市场需求
- 早期参与者获得流动性收益

### 场景 6: 大项目方创建官方市场

**参与者**: SOL 基金会

**前置条件**:
- SOL 是市值前 10 的项目
- SOL 基金会希望在 Hermes 上线 SOL-USD 市场

**流程**:
1. SOL 基金会准备 100,000 USDC 作为初始流动性
2. 提交创建市场消息:
   - Ticker: "SOL-USD"
   - LiquidityTier: Large-Cap
   - VaultDeposit: 100,000 USDC
3. 系统创建市场:
   - 应用 Large-Cap 参数: 初始保证金率 5%, 最大杠杆 20x
   - 存入 100,000 USDC 到 Megavault
4. 市场创建成功
5. SOL 基金会在社交媒体宣传
6. 大量交易者开始交易 SOL-USD
7. SOL 基金会的 Vault 份额随做市盈利增值

**后置条件**: SOL-USD 市场成为热门市场,基金会获得流动性收益

**业务价值**:
- 项目方无需审批,自主上市
- 大额流动性保证市场成功
- 项目方和系统双赢

### 场景 7: 硬上限保护机制

**参与者**: 系统管理员,用户 Frank

**前置条件**:
- 系统已有 999 个市场
- 硬上限 = 1,000 个市场

**流程**:
1. 用户 Frank 创建 TOKEN1-USD 市场,成功 (第 1,000 个)
2. 用户 Grace 尝试创建 TOKEN2-USD 市场
3. 系统验证: 市场总数 = 1,000 (达到硬上限)
4. 系统拒绝 Grace 的请求
5. 系统管理员通过治理提议提高硬上限到 2,000
6. 治理通过,硬上限更新为 2,000
7. Grace 再次提交创建请求,成功

**后置条件**: 硬上限保护系统,治理可以调整上限

**业务价值**:
- 防止无限制创建市场
- 保护系统性能
- 治理灵活调整

- 零交易量市场占比
- 市场交易量分布
- 流动性层级分布

**系统容量**:
- 市场总数 / 硬上限比例
- 市场创建趋势
- 硬上限调整历史

## 6. 术语表

| 术语              | 英文                      | 定义                                                    |
|------------------|--------------------------|--------------------------------------------------------|
| 市场上市          | Market Listing           | 创建新的交易市场                                         |
| 无需许可          | Permissionless           | 无需审批,任何人都可以创建                                |
| 流动性层级        | Liquidity Tier           | 风险分级,不同层级有不同保证金要求                         |
| Vault 存款        | Vault Deposit            | 创建市场时存入 Vault 的资金                              |
| 硬上限            | Hard Cap                 | 市场总数的最大限制                                       |
| Large-Cap        | Large-Cap                | 大盘币,市值高,风险低                                     |
| Mid-Cap          | Mid-Cap                  | 中盘币,市值中等                                          |
| Small-Cap        | Small-Cap                | 小盘币,市值低,风险高                                     |
| Meme币           | Meme Coin                | 高波动性,社区驱动的代币                                  |
| 双重存款          | Dual Deposit             | 同时存入新市场 Vault 和 Megavault                        |
| 新 Vault 存款     | New Vault Deposit        | 存入新市场专属 Vault 的资金,仅做市该市场                  |
| 主 Vault 存款     | Main Vault Deposit       | 存入 Megavault 的资金,参与所有市场做市                    |
| 份额锁定          | Share Locking            | 创建市场时铸造的份额被锁定一段时间,防止快速撤资            |
| 锁定期            | Lock-up Period           | 份额锁定的时长,默认 30 天 (2,592,000 区块)               |
| Vault 做市状态    | Vault Quoting Status     | Vault 的运行状态: QUOTING(做市中), STAND_BY(暂停), DEACTIVATED(停用) |
| 自动激活          | Auto-activation          | 创建市场时 Vault 自动设置为做市状态,无需手动激活           |
| Megavault        | Megavault                | 主 Vault,为所有市场提供流动性                            |
| 专属 Vault        | Dedicated Vault          | 为单个市场创建的独立 Vault,仅做市该市场                  |
| 原子精度          | Atomic Resolution        | 价格的最小精度单位,决定价格表示范围                       |
| IML 5x 层级       | Isolated Margin Leverage 5x | 隔离保证金 5 倍杠杆层级,初始保证金率 20%                 |
