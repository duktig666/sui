## 1. 账户模块

### 1.1 概述

账户模块是交易系统的基础，管理用户的子账户、资产持仓和永续合约仓位。

### 1.2 核心概念

#### 1.2.1 子账户标识

子账户通过两个要素唯一标识：

- **钱包地址**：用户的区块链钱包地址
- **子账户编号**：从0开始的整数编号，单个钱包最多可创建128,000个子账户

#### 1.2.2 子账户结构

每个子账户包含以下信息：

- **资产持仓列表**：记录该子账户持有的各类资产数量（如USDC余额）
- **永续仓位列表**：记录该子账户持有的各永续合约仓位

#### 1.2.3 资产持仓

资产持仓记录用户持有的抵押品资产：

- **资产编号**：标识资产类型，0代表USDC
- **持仓数量**：以最小单位（quantums）计量
- **结算索引**：用于追踪收益结算状态

#### 1.2.4 永续仓位

永续仓位记录用户的合约持仓：

- **合约编号**：标识永续合约类型
- **仓位大小**：正数表示多头，负数表示空头
- **资金费率索引**：记录上次结算时的资金费率累积值
- **仓位余额**：该仓位专属的USDC余额，逐仓模式下使用

### 1.3 保证金模式

#### 1.3.1 全仓模式

**业务定义**： 全仓模式下，用户的所有永续合约仓位共享同一个抵押品池。盈利仓位产生的浮盈可以弥补亏损仓位的浮亏，从而提高资金利用效率。

**主要特点**：

- 所有仓位共享一个统一的抵押品池
- 盈利仓位可以抵消亏损仓位
- 资金利用效率更高
- 适合专业交易者和套利策略

**资金流向**： 交易成交时，盈亏直接反映在子账户的资产持仓（USDC余额）中，仓位的专属余额保持为零。

#### 1.3.2 逐仓模式

**业务定义**： 逐仓模式下，每个永续合约仓位拥有独立的抵押品池。单个仓位的亏损不会影响其他仓位，风险更加可控。

**主要特点**：

- 每个仓位有独立的抵押品池
- 单个仓位亏损不影响其他仓位
- 风险更可控，最大亏损可预期
- 每个子账户只能持有一个逐仓仓位

**资金流向**：

- 开仓时，从主账户划转资金到仓位专属余额
- 平仓时，仓位专属余额划转回主账户

### 1.4 仓位余额机制

仓位余额是存储在永续仓位结构中的USDC余额，用途包括：

1. **逐仓模式**：存储该仓位的专属抵押品，与其他仓位隔离
2. **全仓模式**：通常为零，资金在资产持仓中统一管理
3. **自动保证金调整**：当仓位欠抵押时，系统可从主账户自动补充

### 1.5 业务流程示例

#### 示例1：用户开仓流程

**场景**：新用户存入10,000 USDC后，开立BTC多头仓位

**步骤说明**：

**第一步：存款**

- 用户向系统存入10,000 USDC
- 系统为用户创建子账户（编号0）
- 资产持仓记录为10,000 USDC（以quantums计：10,000,000,000）

**第二步：开仓（全仓模式）**

- 用户提交买单：0.1 BTC，价格50,000美元
- 订单成交，名义价值5,000美元
- 扣除手续费（假设0.05%）：2.5美元
- 最终状态：
  - USDC余额：9,997.5美元（扣除手续费）
  - BTC仓位：+0.1 BTC
  - 仓位余额：0（全仓模式）

#### 示例2：全仓与逐仓对比

**场景**：用5,000 USDC开立ETH多头仓位

**全仓模式下**：

- 初始USDC余额：10,000美元
- 成交后：
  - USDC余额：9,997.5美元（仅扣手续费）
  - ETH仓位大小：按成交量
  - 仓位余额：0

**逐仓模式下**：

- 初始USDC余额：10,000美元
- 成交后：
  - USDC余额：4,997.5美元（划转5,000到仓位，扣手续费）
  - ETH仓位大小：按成交量
  - 仓位余额：5,000美元（作为该仓位专属抵押品）

## 2. 资产模块

### 2.1 概述

资产模块定义和管理系统中的所有资产类型，目前主要支持USDC作为抵押品。

### 2.2 核心概念

#### 2.2.1 资产定义

每种资产包含以下属性：

- **资产编号**：唯一标识符，USDC为0号
- **符号**：显示名称，如"USDC"
- **链上面额**：区块链原生表示
- **面额指数**：链上单位与标准单位的换算指数
- **原子分辨率**：系统内部计量的精度指数

#### 2.2.2 USDC作为主抵押品

USDC是系统的唯一抵押品资产，配置参数：

- 资产编号：0
- 符号：USDC
- 原子分辨率：-6（即1 USDC = 1,000,000 quantums）

### 2.3 单位换算

#### 2.3.1 Quantums概念

**业务定义**： Quantums是系统内部使用的最小计量单位。所有金额在链上以quantums存储和计算，避免浮点数精度问题。

#### 2.3.2 换算规则

**从标准单位到quantums**：

- quantums数量 = 标准数量 × 10的精度次方
- 对于USDC：quantums = USDC数量 × 1,000,000

**从quantums到标准单位**：

- 标准数量 = quantums数量 ÷ 1,000,000

#### 2.3.3 换算示例

**存入100 USDC**：

- 标准数量：100 USDC
- 换算：100 × 1,000,000 = 100,000,000 quantums
- 系统存储：100,000,000

**验证**：

- 100,000,000 ÷ 1,000,000 = 100 USDC ✓

### 2.4 业务流程示例

#### 示例：存取款流程

**场景**：用户存入1,000 USDC，交易盈利后提取500 USDC

**第一步：存入1,000 USDC**

- 链上转账：1,000,000,000 最小单位
- 系统记录：1,000,000,000 quantums
- 账户显示：1,000 USDC

**第二步：交易盈利200 USDC**

- 账户更新：1,200,000,000 quantums
- 账户显示：1,200 USDC

**第三步：提取500 USDC**

- 提取数量：500,000,000 quantums
- 链上转出：500,000,000 最小单位
- 账户剩余：700,000,000 quantums（700 USDC）

## 3. 风险控制

### 3.1 概述

风险控制模块是保障系统安全的核心，通过计算账户健康度和保证金要求来判断账户状态并触发相应操作。

### 3.2 核心指标

#### 3.2.1 三大风险指标

| 指标           | 英文缩写 | 含义                         |
| -------------- | -------- | ---------------------------- |
| 净抵押品       | NC       | 账户的实际净资产价值         |
| 初始保证金要求 | IMR      | 开仓或加仓所需的最低保证金   |
| 维持保证金要求 | MMR      | 维持现有仓位所需的最低保证金 |

#### 3.2.2 账户健康状态

| 状态 | 判断条件       | 业务含义             | 允许的操作       |
| ---- | -------------- | -------------------- | ---------------- |
| 健康 | NC ≥ IMR       | 账户抵押充足         | 开仓、加仓、提取 |
| 警告 | IMR > NC ≥ MMR | 抵押不足但未触发清算 | 仅减仓、充值     |
| 清算 | NC < MMR       | 需要强制平仓         | 被系统清算       |

### 3.3 净抵押品计算

#### 3.3.1 计算公式

**净抵押品 = 资产价值总和 + 仓位净值总和**

其中：

- **资产价值**：各资产持仓的美元价值（USDC按1:1计算）
- **仓位净值**：仓位名义价值 + 仓位余额 + 未结算资金费

#### 3.3.2 仓位名义价值

**名义价值 = |仓位大小| × 预言机价格**

例如：持有0.1 BTC，当前价格50,000美元

- 名义价值 = 0.1 × 50,000 = 5,000美元

### 3.4 保证金要求计算

#### 3.4.1 初始保证金（IMR）

**初始保证金 = 名义价值 × 调整后初始保证金率**

初始保证金率由流动性层级和OIMF机制共同决定。

#### 3.4.2 维持保证金（MMR）

**维持保证金 = 初始保证金 × 维持保证金比例**

典型配置：维持保证金比例为50%，即维持保证金是初始保证金的一半。

### 3.5 OIMF机制（开仓量保证金调整）

#### 3.5.1 机制说明

**业务定义**： OIMF（Open Interest Margin Fraction）是一种动态保证金机制，根据市场总开仓量自动调整初始保证金率。当市场风险较高（开仓量大）时，系统自动提高保证金要求，降低杠杆倍数。

**设计目的**：

- 在低风险时允许更高杠杆，提高资金效率
- 在高风险时降低杠杆，保护系统安全
- 平滑过渡，避免突然的保证金变化

#### 3.5.2 调整规则

**设定参数**：

- 基础初始保证金率（base_IMF）：如5%
- 开仓量下限（lower_cap）：如1,000万美元
- 开仓量上限（upper_cap）：如5,000万美元

**三种情况**：

**情况一：开仓量 ≤ 下限**

- 调整后保证金率 = 基础保证金率
- 杠杆保持最大值

**情况二：下限 < 开仓量 < 上限**

- 保证金率在基础值和100%之间线性插值
- 缩放因子 = (开仓量 - 下限) ÷ (上限 - 下限)
- 调整后保证金率 = 基础保证金率 + 缩放因子 × (100% - 基础保证金率)

**情况三：开仓量 ≥ 上限**

- 调整后保证金率 = 100%
- 杠杆降至1倍（需要全额抵押）

#### 3.5.3 OIMF调整示例

**配置参数**：

- 基础保证金率：5%（对应20倍杠杆）
- 下限：1,000万美元
- 上限：5,000万美元

**不同开仓量下的保证金率**：

| 市场开仓量        | 调整后保证金率 | 最大杠杆 |
| ----------------- | -------------- | -------- |
| 500万美元         | 5%             | 20倍     |
| 1,000万美元       | 5%             | 20倍     |
| 2,000万美元       | 28.75%         | 3.5倍    |
| 3,000万美元       | 52.5%          | 1.9倍    |
| 5,000万美元及以上 | 100%           | 1倍      |

**计算过程（开仓量2,000万美元）**：

- 缩放因子 = (2,000万 - 1,000万) ÷ (5,000万 - 1,000万) = 0.25
- 调整后保证金率 = 5% + 0.25 × (100% - 5%) = 5% + 23.75% = 28.75%

### 3.6 业务流程示例

#### 示例1：账户健康度计算

**场景**：计算用户账户的健康状态

**账户持仓**：

- USDC余额：5,000美元
- BTC多头：0.2 BTC，当前价格50,000美元（名义价值10,000美元）
- ETH空头：2 ETH，当前价格3,000美元（名义价值6,000美元）

**配置参数**：

- BTC初始保证金率：5%
- ETH初始保证金率：10%
- 维持保证金比例：50%
- 当前开仓量均低于下限（不触发OIMF调整）

**计算过程**：

**第一步：计算净抵押品（NC）**

- USDC价值：5,000美元
- 假设仓位盈亏为零
- NC = 5,000 + 0 + 0 = 5,000美元

**第二步：计算初始保证金（IMR）**

- BTC的IMR = 10,000 × 5% = 500美元
- ETH的IMR = 6,000 × 10% = 600美元
- 总IMR = 500 + 600 = 1,100美元

**第三步：计算维持保证金（MMR）**

- BTC的MMR = 500 × 50% = 250美元
- ETH的MMR = 600 × 50% = 300美元
- 总MMR = 250 + 300 = 550美元

**第四步：判断状态**

- NC（5,000）≥ IMR（1,100）？是 ✓
- 结论：账户健康，可以继续交易

#### 示例2：OIMF触发场景

**场景**：市场开仓量上升导致保证金要求增加

**初始状态**：

- 用户净抵押品：1,000美元
- 持有BTC多头，名义价值10,000美元
- 市场开仓量：800万美元（低于下限）
- 初始保证金 = 10,000 × 5% = 500美元
- 维持保证金 = 500 × 50% = 250美元
- 状态：健康（NC 1,000 > IMR 500）

**开仓量上升后**：

- 市场开仓量：3,000万美元
- 调整后保证金率 = 52.5%
- 新初始保证金 = 10,000 × 52.5% = 5,250美元
- 新维持保证金 = 5,250 × 50% = 2,625美元
- NC（1,000）< MMR（2,625）
- 状态：触发清算！

**结论**： OIMF机制会在市场风险上升时自动提高保证金要求。即使价格没有变化，账户也可能因为市场开仓量上升而触发清算。

## 4. 上币与市场模块

### 4.1 概述

上币与市场模块管理交易对的创建、配置和状态转换。

### 4.2 核心概念

#### 4.2.1 交易对定义

每个交易对包含以下属性：

- **交易对编号**：唯一标识符
- **关联合约**：对应的永续合约编号
- **最小数量单位**：订单数量必须是此值的整数倍
- **最小价格单位**：订单价格必须是此值的整数倍
- **转换指数**：数量到报价量的换算指数
- **状态**：交易对当前的运行状态

#### 4.2.2 交易对状态

| 状态     | 说明                   | 允许的操作    |
| -------- | ---------------------- | ------------- |
| 正常交易 | 市场正常运行           | 所有操作      |
| 暂停     | 临时暂停交易           | 仅取消订单    |
| 仅取消   | 仅允许取消订单         | 取消订单      |
| 仅挂单   | 仅允许挂单，不立即成交 | Post-Only订单 |
| 初始化中 | 市场正在初始化         | Post-Only订单 |
| 最终结算 | 市场进入结算阶段       | 强制平仓      |

### 4.3 精度参数

#### 4.3.1 最小数量单位

**业务定义**： 订单数量必须是最小数量单位的整数倍。这确保了订单的标准化，便于撮合和结算。

**示例（BTC-USD）**：

- 最小数量单位 = 0.0001 BTC
- 有效订单数量：0.0001, 0.0002, 0.01, 0.1 BTC
- 无效订单数量：0.00005, 0.00015 BTC

#### 4.3.2 最小价格单位

**业务定义**： 订单价格必须是最小价格单位的整数倍。这确保了价格的标准化。

**示例（BTC-USD）**：

- 最小价格单位 = 1美元
- 有效价格：50,000, 50,001, 50,100美元
- 无效价格：50,000.5, 50,000.75美元

### 4.4 业务流程示例

#### 示例：订单有效性验证

**交易对配置（BTC-USD）**：

- 最小数量单位：0.0001 BTC
- 最小价格单位：1美元

**验证订单**：买入0.05 BTC，价格50,000美元

**数量验证**：

- 0.05 ÷ 0.0001 = 500（整数） ✓
- 数量有效

**价格验证**：

- 50,000 ÷ 1 = 50,000（整数） ✓
- 价格有效

**结论**：订单有效，可以提交

## 5. 价格预言机

### 5.1 概述

价格预言机模块提供可靠的市场价格数据，用于保证金计算、清算判断和资金费率计算。

### 5.2 核心概念

#### 5.2.1 市场价格

每个市场的价格包含：

- **市场编号**：标识市场
- **价格指数**：用于将存储值转换为实际价格的指数
- **价格值**：以整数存储的价格

#### 5.2.2 价格换算

**实际价格 = 存储价格值 × 10的指数次方**

示例（BTC-USD）：

- 存储价格值：5,000,000,000
- 指数：-5
- 实际价格 = 5,000,000,000 × 0.00001 = 50,000美元

### 5.3 价格更新机制

#### 5.3.1 数据来源

价格数据通过专门的预言机系统获取：

- 验证者节点收集外部价格数据
- 通过共识机制确定中位数价格
- 更新到链上状态

#### 5.3.2 更新验证

为防止频繁的无意义更新，系统设置最小价格变化阈值：

**验证规则**：

- 价格变化率 = |新价格 - 旧价格| ÷ 旧价格
- 只有当变化率超过最小阈值时，才接受更新

### 5.4 业务流程示例

#### 示例：价格更新验证

**当前状态**：

- BTC当前价格：50,000美元
- 最小价格变化阈值：0.005%（50 ppm）

**场景一：小幅价格变化**

- 新价格提案：50,002美元
- 变化率 = |50,002 - 50,000| ÷ 50,000 = 0.004%
- 0.004% < 0.005%
- 结果：拒绝更新

**场景二：有效价格变化**

- 新价格提案：50,030美元
- 变化率 = |50,030 - 50,000| ÷ 50,000 = 0.06%
- 0.06% > 0.005%
- 结果：接受更新

## 6. 合约模块

### 6.1 概述

合约模块定义永续合约的参数、资金费率索引和开仓量，是交易系统的核心。

### 6.2 核心概念

#### 6.2.1 永续合约

每个永续合约包含：

- **合约参数**：基本配置信息
- **资金费率索引**：资金费率累积值
- **开仓量**：当前市场总开仓量

#### 6.2.2 合约参数

- **合约编号**：唯一标识符
- **交易对符号**：如"BTC-USD"
- **关联价格市场**：获取价格的市场编号
- **原子分辨率**：数量计量精度
- **默认资金费率**：基准资金费率
- **流动性层级**：确定保证金率的层级编号
- **保证金类型**：全仓或逐仓

#### 6.2.3 保证金类型

| 类型 | 说明                 |
| ---- | -------------------- |
| 全仓 | 所有仓位共享抵押品池 |
| 逐仓 | 每个仓位独立抵押品池 |

### 6.3 流动性层级

#### 6.3.1 层级定义

流动性层级决定了合约的保证金参数：

- **层级编号**：唯一标识
- **层级名称**：如"大盘币"、"中盘币"
- **初始保证金率**：开仓所需保证金比例
- **维持保证金比例**：维持保证金占初始保证金的比例
- **影响名义价值**：用于计算价格溢价的标准订单金额
- **开仓量上下限**：OIMF机制的触发参数

#### 6.3.2 典型配置

| 层级 | 名称   | 初始保证金率 | 维持保证金比例 | 最大杠杆 |
| ---- | ------ | ------------ | -------------- | -------- |
| 0    | 大盘币 | 5%           | 60%            | 20倍     |
| 1    | 中盘币 | 10%          | 50%            | 10倍     |
| 2    | 小盘币 | 20%          | 50%            | 5倍      |
| 3    | 长尾币 | 100%         | 100%           | 1倍      |

### 6.4 核心公式

#### 6.4.1 维持保证金率计算

**维持保证金率 = 初始保证金率 × 维持保证金比例**

示例（大盘币）：

- 初始保证金率：5%
- 维持保证金比例：60%
- 维持保证金率 = 5% × 60% = 3%

#### 6.4.2 资金费率钳制上限

**最大资金费率 = 钳制因子 × (初始保证金率 - 维持保证金率)**

示例：

- 钳制因子：600%
- 初始保证金率：5%
- 维持保证金率：3%
- 最大资金费率 = 600% × (5% - 3%) = 12%

### 6.5 影响名义价值

#### 6.5.1 业务定义

影响名义价值（Impact Notional）是用于计算价格溢价的标准化订单金额。它模拟一个固定金额的市价单对订单簿的影响。

#### 6.5.2 用途

1. **计算影响买价**：买入影响名义价值金额的平均成交价
2. **计算影响卖价**：卖出影响名义价值金额的平均成交价
3. **确定价格溢价**：根据影响价格与指数价格的偏差计算溢价
4. **资金费率计算**：溢价是资金费率计算的核心输入

### 6.6 业务流程示例

#### 示例：不同流动性层级的保证金要求对比

**场景**：开立10,000美元名义价值的仓位

**大盘币（BTC）**：

- 初始保证金率：5%
- 维持保证金比例：60%
- 初始保证金 = 10,000 × 5% = 500美元
- 维持保证金 = 500 × 60% = 300美元
- 最大杠杆：20倍

**中盘币（LINK）**：

- 初始保证金率：10%
- 维持保证金比例：50%
- 初始保证金 = 10,000 × 10% = 1,000美元
- 维持保证金 = 1,000 × 50% = 500美元
- 最大杠杆：10倍

**小盘币（DOGE）**：

- 初始保证金率：20%
- 维持保证金比例：50%
- 初始保证金 = 10,000 × 20% = 2,000美元
- 维持保证金 = 2,000 × 50% = 1,000美元
- 最大杠杆：5倍

**结论**：流动性越差的资产，保证金要求越高，杠杆倍数越低。

## 7. 撮合结算模块

### 7.1 概述

撮合结算模块是交易系统的核心，负责订单匹配、成交和余额更新。

### 7.2 订单类型

#### 7.2.1 按生命周期分类

| 类型     | 有效期       | 存储方式 | 适用场景 |
| -------- | ------------ | -------- | -------- |
| 短期订单 | 最多20个区块 | 仅内存   | 高频交易 |
| 长期订单 | 最长90天     | 链上状态 | 挂单策略 |
| 条件订单 | 最长90天     | 链上状态 | 止损止盈 |
| TWAP订单 | 5分钟-24小时 | 链上状态 | 大单拆分 |

#### 7.2.2 执行方式

| 类型        | 说明                                  |
| ----------- | ------------------------------------- |
| 限价单      | 指定价格，等待成交                    |
| IOC         | 立即成交或取消（Immediate-Or-Cancel） |
| Post-Only   | 确保作为挂单方成交，享受Maker费率     |
| Reduce-Only | 仅减少仓位，不增加仓位                |

### 7.3 订单结构

每个订单包含以下信息：

- **订单标识**：子账户ID + 客户端ID + 订单类型 + 交易对
- **方向**：买入或卖出
- **数量**：订单数量（quantums）
- **价格**：订单价格（subticks）
- **有效期**：过期区块或时间
- **执行条件**：时效类型、是否仅减仓、条件触发价等

### 7.4 撮合流程

#### 7.4.1 单笔撮合步骤

**输入**：

- 吃单方（Taker）订单
- 挂单方（Maker）订单
- 成交数量

**处理步骤**：

1. 验证交易对有效性和状态
2. 验证成交数量是最小数量单位的整数倍
3. 计算报价量（成交金额）
4. 获取双方的费率层级
5. 计算双方手续费
6. 更新双方余额和仓位
7. 处理收入分成（推荐人返佣等）
8. 发出成交事件

### 7.5 核心公式

#### 7.5.1 报价量计算

**报价量 = 成交数量 × 成交价格 × 转换系数**

示例：

- 成交数量：0.01 BTC
- 成交价格：50,000美元
- 报价量 = 0.01 × 50,000 = 500美元

#### 7.5.2 手续费计算

**手续费 = 报价量 × 费率**

示例：

- 报价量：5,000美元
- Taker费率：0.05%
- Maker费率：-0.02%（返佣）
- Taker手续费 = 5,000 × 0.05% = 2.5美元
- Maker返佣 = 5,000 × 0.02% = 1美元

### 7.6 业务流程示例

#### 示例：一笔BTC交易的完整撮合结算

**场景**：Alice买入0.1 BTC，Bob卖出0.1 BTC，成交价50,000美元

**初始状态**：

- Alice：USDC余额10,000美元，BTC仓位0
- Bob：USDC余额5,000美元，BTC多头0.5 BTC
- 订单簿：Bob挂卖单0.5 BTC，价格50,000美元

**第一步：Alice提交买单**

- 订单类型：IOC（立即成交或取消）
- 数量：0.1 BTC
- 价格：50,000美元

**第二步：撮合引擎匹配**

- 找到Bob的卖单
- 成交数量：0.1 BTC
- 成交价格：50,000美元

**第三步：计算报价量**

- 报价量 = 0.1 × 50,000 = 5,000美元

**第四步：计算手续费**

- Alice（Taker）：5,000 × 0.05% = 2.5美元
- Bob（Maker）：5,000 × (-0.02%) = -1美元（获得返佣）

**第五步：更新Alice余额（买方）**

- USDC变化 = -报价量 - Taker费 = -5,000 - 2.5 = -5,002.5美元
- 新USDC余额 = 10,000 - 5,002.5 = 4,997.5美元
- 新BTC仓位 = 0 + 0.1 = 0.1 BTC

**第六步：更新Bob余额（卖方）**

- USDC变化 = +报价量 + 返佣 = +5,000 + 1 = +5,001美元
- 新USDC余额 = 5,000 + 5,001 = 10,001美元
- 新BTC仓位 = 0.5 - 0.1 = 0.4 BTC

**最终状态**：

- Alice：USDC 4,997.5美元，BTC仓位+0.1 BTC
- Bob：USDC 10,001美元，BTC仓位+0.4 BTC
- 协议手续费收入 = 2.5 - 1 = 1.5美元

## 8. 资金费率模块

### 8.1 概述

资金费率机制是永续合约锚定现货价格的核心，通过定期在多空双方之间转移资金来调节合约价格。

### 8.2 两阶段处理机制

#### 8.2.1 第一阶段：溢价采样（每分钟）

**处理内容**：

- 收集验证者的溢价投票
- 计算中位数得到溢价样本
- 存储溢价样本

#### 8.2.2 第二阶段：资金费率计算（每小时）

**处理内容**：

- 聚合过去60个溢价样本
- 计算平均值并加上默认资金费率
- 对资金费率进行钳制
- 计算资金费率索引增量
- 更新永续合约的资金费率索引
- 清空溢价样本

### 8.3 溢价计算

#### 8.3.1 影响价格计算

**影响买价**：买入"影响名义价值"金额的平均成交价 **影响卖价**：卖出"影响名义价值"金额的平均成交价

如果订单簿深度不足以吸收影响名义价值，则认为流动性不足，溢价设为0。

#### 8.3.2 溢价公式

设指数价格为Index，影响买价为ImpactBid，影响卖价为ImpactAsk

**情况一：指数价格低于影响卖价（市场偏多）**

- 条件：Index < ImpactBid
- 溢价 = ImpactBid ÷ Index - 1（正溢价，多头付费）

**情况二：价格平衡区间**

- 条件：ImpactBid ≤ Index ≤ ImpactAsk
- 溢价 = 0

**情况三：指数价格高于影响买价（市场偏空）**

- 条件：ImpactAsk < Index
- 溢价 = ImpactAsk ÷ Index - 1（负溢价，空头付费）

### 8.4 资金费率计算

#### 8.4.1 最终费率公式

**第一步：聚合溢价样本**

- 移除极端值后取平均

**第二步：计算原始资金费率**

- 原始资金费率 = 平均溢价 + 默认资金费率

**第三步：钳制资金费率**

- 最大钳制值 = 钳制因子 × (初始保证金率 - 维持保证金率)
- 最终资金费率 = 钳制(原始资金费率, -最大钳制值, +最大钳制值)

#### 8.4.2 资金费率索引增量

**索引增量 = 资金费率 × (距上次结算时间 ÷ 8小时) × 预言机价格**

说明：

- 资金费率是8小时的费率
- 每小时更新一次，所以实际增量是资金费率的1/8

### 8.5 资金费结算

#### 8.5.1 结算公式

**资金费支付 = 仓位大小 × (当前资金费率索引 - 上次结算索引)**

结果解读：

- 正值：用户支付资金费（多头在正费率时）
- 负值：用户收取资金费（空头在正费率时）

### 8.6 业务流程示例

#### 示例：8小时资金费率计算

**配置参数**：

- 默认资金费率：0
- 钳制因子：600%
- 初始保证金率：5%
- 维持保证金率：3%
- 影响名义价值：500,000美元
- 预言机价格：50,000美元

**第一步：每分钟收集溢价**

当前订单簿状态：

- 最佳买价：49,950美元，深度10 BTC
- 最佳卖价：50,050美元，深度10 BTC

计算影响价格：

- 买入500,000美元需要约10 BTC，平均成交价（影响买价）= 50,050美元
- 卖出500,000美元需要约10 BTC，平均成交价（影响卖价）= 49,950美元

判断溢价：

- 指数价格：50,000美元
- 影响卖价（49,950）< 指数（50,000）< 影响买价（50,050）
- 结论：价格平衡，溢价 = 0

**第二步：市场偏多场景**

假设订单簿变化，最佳买价上升到50,100美元：

- 影响卖价 = 50,080美元
- 指数价格 = 50,000美元
- 判断：指数（50,000）< 影响卖价（50,080）
- 溢价 = 50,080 ÷ 50,000 - 1 = 0.16%

**第三步：每小时聚合**

假设过去60个溢价样本的平均值为0.08%（800 ppm）

计算资金费率：

- 原始资金费率 = 0.08% + 0（默认）= 0.08%
- 计算钳制上限 = 600% × (5% - 3%) = 12%
- 0.08% < 12%，无需钳制
- 最终资金费率 = 0.08%（每8小时）

**第四步：计算索引增量**

- 距上次结算：1小时
- 索引增量 = 0.08% × (1 ÷ 8) × 50,000美元 = 5美元/BTC

**第五步：用户资金费结算**

Alice持有0.1 BTC多头：

- 上次结算索引：100
- 当前索引：105
- 资金费支付 = 0.1 × (105 - 100) = 0.5美元
- Alice支付0.5美元资金费（多头在正费率时支付）

Bob持有0.1 BTC空头：

- 资金费支付 = -0.1 × (105 - 100) = -0.5美元
- Bob收取0.5美元资金费（空头在正费率时收取）

## 9. 清算模块

### 9.1 概述

清算模块负责处理资不抵债的账户，保护系统免受坏账风险。当账户的净抵押品不足以支撑其仓位的维持保证金要求时，系统将强制平仓以防止坏账产生。

### 9.2 清算触发条件

#### 9.2.1 触发条件公式

**清算触发条件**：同时满足以下两个条件

1. 维持保证金要求 > 0（账户有仓位）
2. 维持保证金要求 > 净抵押品（账户欠抵押）

用数学表达式表示：

**MMR > 0 且 MMR > NC**

或等价于：

**NC < MMR（当 MMR > 0 时）**

#### 9.2.2 触发价格计算

**业务定义**： 触发清算价格是使账户净抵押品恰好等于维持保证金要求时的价格。当市场价格突破此价格时，账户将被清算。

**多头仓位触发价格**：

触发价格 = 开仓均价 × (1 - 可用保证金率 + 维持保证金率)

其中：

- 开仓均价 = 开仓成本 ÷ 仓位大小
- 可用保证金率 = (USDC余额 + 仓位余额) ÷ 名义价值
- 维持保证金率 = 初始保证金率 × 维持保证金比例

**空头仓位触发价格**：

触发价格 = 开仓均价 × (1 + 可用保证金率 - 维持保证金率)

#### 9.2.3 触发价格示例

**场景**：计算多头仓位的清算触发价格

**账户状态**：

- 仓位：+1 BTC 多头
- 开仓均价：50,000美元
- USDC余额：3,000美元
- 仓位余额：0美元（全仓模式）
- 初始保证金率：5%
- 维持保证金比例：50%

**计算过程**：

- 名义价值（按开仓价）= 1 × 50,000 = 50,000美元
- 可用保证金率 = 3,000 ÷ 50,000 = 6%
- 维持保证金率 = 5% × 50% = 2.5%
- 触发价格 = 50,000 × (1 - 6% + 2.5%) = 50,000 × 96.5% = 48,250美元

**验证**：当价格跌至48,250美元时

- 名义价值 = 1 × 48,250 = 48,250美元
- 未实现亏损 = 50,000 - 48,250 = 1,750美元
- 净抵押品 = 3,000 - 1,750 = 1,250美元
- 初始保证金 = 48,250 × 5% = 2,412.5美元
- 维持保证金 = 2,412.5 × 50% = 1,206.25美元
- NC (1,250) ≈ MMR (1,206.25) → 触发清算边界

### 9.3 破产价格

#### 9.3.1 破产价格定义

**业务定义**： 破产价格是假设以该价格完全平仓后，账户净资产恰好为零的价格。这是清算的理论基准价格，系统在此基础上设定实际清算价格。

#### 9.3.2 破产价格公式

**核心公式**（以报价金额表示）：

破产价报价量 = -仓位名义价值变化 - (账户净抵押品 × |仓位维持保证金变化| ÷ 账户总维持保证金)

用符号表示：

**Bankruptcy_Quote = -ΔNNV - (TNC × |ΔMMR| ÷ TMMR)**

其中：

- **ΔNNV**（仓位名义价值变化）：平仓后仓位名义价值的变化量
- **TNC**（账户净抵押品）：账户的总净抵押品
- **ΔMMR**（仓位维持保证金变化）：平仓该仓位后维持保证金的变化（减少，故为负值）
- **TMMR**（账户总维持保证金）：账户的总维持保证金要求

**简化理解**：

对于单一仓位账户：

- **多头破产价** = (名义价值 - 净抵押品) ÷ 仓位大小
- **空头破产价** = (名义价值 + 净抵押品) ÷ |仓位大小|

#### 9.3.3 破产价格公式推导

**推导逻辑**：

设账户以破产价平仓后净资产为零，则：

- 平仓收入 - 原有净抵押品的消耗 = 0
- 平仓收入 = 原有净抵押品 × (该仓位维持保证金 ÷ 总维持保证金)

这意味着每个仓位按其维持保证金占比分配账户的剩余净抵押品。

#### 9.3.4 破产价格示例

**场景**：计算多头仓位的破产价格

**账户状态**：

- 仓位：+0.5 BTC 多头
- 当前价格：48,000美元
- 名义价值：0.5 × 48,000 = 24,000美元
- USDC余额：200美元
- 未实现亏损：假设开仓价50,000美元，亏损 = 0.5 × (50,000 - 48,000) = 1,000美元
- 净抵押品(TNC) = 200 + (-1,000) = -800美元（已为负）
- 仓位维持保证金(PMMR) = 24,000 × 5% × 50% = 600美元
- 账户总维持保证金(TMMR) = 600美元（单一仓位）

**计算破产价**：

方法一（简化公式）：

- 破产价 = (名义价值 - 净抵押品) ÷ 仓位大小
- 破产价 = (24,000 - (-800)) ÷ 0.5 = 24,800 ÷ 0.5 = 49,600美元

方法二（完整公式）：

- 平仓后仓位名义价值变化(ΔNNV) = 0 - 24,000 = -24,000美元
- 仓位维持保证金变化(ΔMMR) = 0 - 600 = -600美元
- 破产价报价量 = -(-24,000) - (-800 × |-600| ÷ 600)
- 破产价报价量 = 24,000 - (-800 × 1) = 24,000 + 800 = 24,800美元
- 破产价 = 24,800 ÷ 0.5 = 49,600美元

**注意**：由于净抵押品已为负，破产价高于当前价格，意味着即使价格上涨到49,600美元平仓，账户也只能刚好还清债务。

### 9.4 可成交价格（实际清算价格）

#### 9.4.1 可成交价格定义

**业务定义**： 可成交价格是实际清算订单的挂单价格。它在破产价格基础上增加一定价差，目的是：

1. 为清算订单提供竞争力，确保能够成交
2. 在价格有利时为保险基金创造收入
3. 控制对市场的冲击

#### 9.4.2 可成交价格公式

**核心公式**：

可成交价格 = (仓位名义价值 - 调整后破产系数 × 价差比率 × 仓位维持保证金) ÷ 仓位大小

用符号表示：

**Fillable_Price = (PNNV - ABR × SMMR × PMMR) ÷ PS**

其中：

- **PNNV**（仓位名义价值）：仓位按预言机价格计算的名义价值
- **ABR**（调整后破产系数）：反映账户风险程度的系数，范围[0, 1]
- **SMMR**（价差与维持保证金比率）：配置参数，如5%
- **PMMR**（仓位维持保证金）：该仓位的维持保证金要求
- **PS**（仓位大小）：仓位数量（正数为多头，负数为空头）

#### 9.4.3 调整后破产系数(ABR)

**计算公式**：

ABR = BA × (1 - TNC ÷ TMMR)，钳制到[0, 1]范围

其中：

- **BA**（破产调整基数）：配置参数，如100%
- **TNC**（账户净抵押品）
- **TMMR**（账户总维持保证金）

**ABR的含义**：

- 当 TNC = TMMR（刚好触发清算）：ABR = BA × (1 - 1) = 0 → 可成交价 ≈ 预言机价
- 当 TNC = 0（净抵押品为零）：ABR = BA × (1 - 0) = BA → 可成交价有较大价差
- 当 TNC < 0（净抵押品为负）：ABR = BA × (1 - 负数) > BA，钳制为1 → 最大价差

#### 9.4.4 可成交价格示例

**场景**：计算实际清算订单价格

**账户状态**：

- 仓位：+1 BTC 多头
- 预言机价格：48,000美元
- 仓位名义价值(PNNV)：48,000美元
- 净抵押品(TNC)：500美元
- 初始保证金率：5%
- 维持保证金比例：50%
- 仓位维持保证金(PMMR)：48,000 × 5% × 50% = 1,200美元
- 账户总维持保证金(TMMR)：1,200美元

**配置参数**：

- 破产调整基数(BA)：100%（1,000,000 ppm）
- 价差与维持保证金比率(SMMR)：5%（50,000 ppm）

**计算过程**：

**第一步：计算调整后破产系数(ABR)**

- TNC ÷ TMMR = 500 ÷ 1,200 = 0.4167
- ABR = 100% × (1 - 0.4167) = 58.33%
- 钳制后ABR = 58.33%（在[0,1]范围内）

**第二步：计算价差金额**

- 最大价差 = SMMR × PMMR = 5% × 1,200 = 60美元
- 实际价差 = ABR × 最大价差 = 58.33% × 60 = 35美元

**第三步：计算可成交价格**

- 可成交价格报价量 = PNNV - 35 = 48,000 - 35 = 47,965美元
- 可成交价格 = 47,965 ÷ 1 = 47,965美元

**结论**：

- 预言机价格：48,000美元
- 可成交价格：47,965美元
- 价差：35美元（0.073%）
- 清算订单将以47,965美元挂卖单

#### 9.4.5 不同风险程度的价差对比

| 账户状态   | TNC/TMMR | ABR          | 价差占MMR比例 | 实际价差 |
| ---------- | -------- | ------------ | ------------- | -------- |
| 刚触发清算 | 100%     | 0%           | 0%            | 0美元    |
| 中等风险   | 50%      | 50%          | 2.5%          | 30美元   |
| 高风险     | 0%       | 100%         | 5%            | 60美元   |
| 已破产     | -50%     | 100%（钳制） | 5%            | 60美元   |

### 9.5 保险基金机制

#### 9.5.1 保险基金变化公式

**核心公式**：

保险基金变化 = 实际成交报价量 - 破产价报价量

用符号表示：

**Insurance_Delta = Fill_Quote - Bankruptcy_Quote**

**结果解读**：

- **正值**：清算有盈余，盈余进入保险基金
- **零值**：清算刚好平衡，无盈亏
- **负值**：清算有亏损，保险基金需要赔付

#### 9.5.2 清算费收取

当保险基金变化为正时，收取清算费：

**清算费 = 较小值(保险基金盈余, 成交金额 × 最大清算费率)**

典型配置：最大清算费率 = 0.5%

#### 9.5.3 保险基金计算示例

**场景**：计算清算的保险基金影响

**清算信息**：

- 清算仓位：+0.1 BTC 多头
- 破产价：48,500美元
- 可成交价：48,200美元
- 实际成交价：48,300美元（订单簿买单价格）
- 最大清算费率：0.5%

**计算过程**：

**第一步：计算各价格对应金额**

- 破产价金额 = 0.1 × 48,500 = 4,850美元
- 实际成交金额 = 0.1 × 48,300 = 4,830美元

**第二步：计算保险基金变化**

- 保险基金变化 = 4,830 - 4,850 = -20美元
- 结果为负，保险基金需赔付20美元

**另一场景：成交价高于破产价**

- 实际成交价：48,600美元
- 实际成交金额 = 0.1 × 48,600 = 4,860美元
- 保险基金变化 = 4,860 - 4,850 = +10美元
- 最大清算费 = 4,860 × 0.5% = 24.3美元
- 实际清算费 = 较小值(10, 24.3) = 10美元
- 保险基金收入10美元

### 9.7 去杠杆机制

#### 9.7.1 触发条件

去杠杆在以下任一情况触发：

1. **流动性不足**：清算订单无法与订单簿成交
2. **保险基金不足**：保险基金余额无法覆盖清算亏损
3. **最终结算**：市场进入最终结算状态

#### 9.7.2 对手方选择

去杠杆需要找到对手方来承接被清算仓位：

1. 确定清算方向（多头被清算则找空头对手方）
2. 获取相反方向的所有账户列表
3. 使用伪随机起点遍历（避免同一账户总被选中）
4. 验证破产价格是否重叠
5. 计算可匹配数量
6. 执行去杠杆

#### 9.7.3 去杠杆成交价格

**负净资产场景**： 成交价 = 被清算方的破产价

**最终结算场景**： 成交价 = 预言机价格

### 9.8 完整清算流程示例

#### 示例1：标准清算流程（详细计算）

**初始状态**：

- 用户：Alice
- 仓位：+2 BTC 多头
- 开仓均价：52,000美元
- USDC余额：2,000美元
- 当前预言机价格：50,000美元
- 初始保证金率：5%
- 维持保证金比例：50%
- 破产调整基数(BA)：100%
- 价差与维持保证金比率(SMMR)：5%
- 最大清算费率：0.5%

**第一步：判断是否触发清算**

计算账户状态：

- 当前名义价值 = 2 × 50,000 = 100,000美元
- 未实现亏损 = 2 × (52,000 - 50,000) = 4,000美元
- 净抵押品(TNC) = 2,000 - 4,000 = -2,000美元
- 初始保证金 = 100,000 × 5% = 5,000美元
- 维持保证金(TMMR) = 5,000 × 50% = 2,500美元

判断：

- MMR (2,500) > 0 ✓
- MMR (2,500) > NC (-2,000) ✓
- 结论：触发清算

**第二步：计算破产价格**

- 仓位名义价值(PNNV) = 100,000美元
- 净抵押品(TNC) = -2,000美元
- 破产价 = (PNNV - TNC) ÷ PS = (100,000 - (-2,000)) ÷ 2 = 51,000美元

验证：以51,000美元平仓

- 平仓收入 = 2 × 51,000 = 102,000美元
- 开仓成本 = 2 × 52,000 = 104,000美元
- 平仓亏损 = 104,000 - 102,000 = 2,000美元
- 最终净资产 = 2,000(USDC) - 2,000(亏损) = 0美元 ✓

**第三步：计算可成交价格**

计算ABR：

- TNC ÷ TMMR = -2,000 ÷ 2,500 = -0.8
- ABR = 100% × (1 - (-0.8)) = 180%
- 钳制后ABR = 100%（超过1，钳制为1）

计算价差：

- 最大价差 = SMMR × PMMR = 5% × 2,500 = 125美元
- 实际价差 = ABR × 最大价差 = 100% × 125 = 125美元

计算可成交价格：

- 可成交价格报价量 = PNNV - 125 = 100,000 - 125 = 99,875美元
- 可成交价格 = 99,875 ÷ 2 = 49,937.5美元

**第四步：清算订单执行**

清算订单：卖出2 BTC @ 49,937.5美元

假设订单簿成交：

- 实际成交价：49,950美元
- 实际成交金额 = 2 × 49,950 = 99,900美元

**第五步：计算保险基金影响**

- 破产价金额 = 2 × 51,000 = 102,000美元
- 实际成交金额 = 99,900美元
- 保险基金变化 = 99,900 - 102,000 = -2,100美元
- 保险基金需赔付2,100美元

**第六步：最终状态**

- Alice：USDC余额0美元，BTC仓位0
- 买方：获得2 BTC @ 49,950美元
- 保险基金：支出2,100美元

#### 示例2：去杠杆触发场景

**场景**：保险基金不足，触发去杠杆

**初始状态**：

- 被清算账户Alice：BTC多头+5 BTC，严重破产
- 破产价：49,000美元
- 可成交价：48,500美元
- 预言机价格：48,000美元
- 保险基金余额：1,000美元
- 预计清算亏损：5,000美元
- 订单簿仅能成交2 BTC

**第一步：部分清算**

- 清算订单：卖出5 BTC @ 48,500美元
- 订单簿成交2 BTC @ 48,200美元
- 成交金额 = 2 × 48,200 = 96,400美元
- 破产价金额 = 2 × 49,000 = 98,000美元
- 保险基金变化 = 96,400 - 98,000 = -1,600美元

**第二步：检查保险基金**

- 需要赔付：1,600美元
- 保险基金余额：1,000美元
- 1,000 < 1,600，余额不足

**第三步：触发去杠杆**

剩余仓位：3 BTC需要去杠杆

寻找对手方：

- 筛选持有BTC空头的账户
- 找到Bob：持有-4 BTC空头
- 验证：Bob的仓位可承接3 BTC

**第四步：执行去杠杆**

- 去杠杆数量：3 BTC
- 去杠杆价格：Alice的破产价 = 49,000美元
- Alice：卖出3 BTC @ 49,000美元，收入147,000美元
- Bob：买入3 BTC @ 49,000美元，支出147,000美元
- Bob的空头从-4 BTC变为-1 BTC

**第五步：最终状态**

- Alice：完全清算，仓位归零
- Bob：空头从-4 BTC变为-1 BTC（被动平仓3 BTC）
- 保险基金：支付1,000美元后归零
- 系统无坏账

### 9.9 清算公式汇总

| 公式名称       | 公式                                       | 说明                           |
| -------------- | ------------------------------------------ | ------------------------------ |
| 清算触发条件   | MMR > 0 且 NC < MMR                        | 维持保证金为正且净抵押品不足   |
| 多头触发价格   | 开仓价 × (1 - 可用保证金率 + 维持保证金率) | 价格跌破此值触发清算           |
| 空头触发价格   | 开仓价 × (1 + 可用保证金率 - 维持保证金率) | 价格涨破此值触发清算           |
| 破产价报价量   | -ΔNNV - (TNC × \|ΔMMR\| ÷ TMMR)            | 平仓后净资产为零的价格对应金额 |
| 多头简化破产价 | (PNNV - TNC) ÷ PS                          | 适用于单仓位账户               |
| 调整后破产系数 | BA × (1 - TNC ÷ TMMR)，钳制到[0,1]         | 反映账户风险程度               |
| 可成交价格     | (PNNV - ABR × SMMR × PMMR) ÷ PS            | 实际清算订单价格               |
| 保险基金变化   | 实际成交金额 - 破产价金额                  | 正值为盈余，负值为亏损         |
| 清算费         | 较小值(盈余, 成交额 × 最大费率)            | 仅在盈余时收取                 |

## 10. 手续费层与收入分成

### 10.1 概述

手续费系统支持多层级费率、推荐人机制和多种收入分成方式。

### 10.2 费率层级

#### 10.2.1 层级结构

每个费率层级包含：

- **层级名称**：如"VIP 0"、"VIP 1"
- **绝对交易量要求**：达到该层级所需的30天交易量
- **Maker费率**：挂单方费率（可为负，表示返佣）
- **Taker费率**：吃单方费率

#### 10.2.2 典型配置

| 层级  | 30天交易量要求 | Maker费率 | Taker费率 |
| ----- | -------------- | --------- | --------- |
| VIP 0 | 0              | 0.02%     | 0.05%     |
| VIP 1 | 100万美元      | 0.015%    | 0.04%     |
| VIP 2 | 500万美元      | 0.01%     | 0.035%    |
| VIP 3 | 2,500万美元    | 0.005%    | 0.03%     |
| VIP 4 | 1.25亿美元     | -0.005%   | 0.025%    |
| VIP 5 | 3.125亿美元    | -0.01%    | 0.02%     |

### 10.3 费率计算流程

**第一步：确定用户费率层级**

- 查询用户30天交易量
- 匹配满足条件的最高层级
- 获取基础Maker和Taker费率

**第二步：应用市场折扣**

- 某些市场可能有额外折扣
- 折扣后费率 = 基础费率 × 市场折扣率

**第三步：应用质押折扣（仅正费率时）**

- 根据用户质押量查询折扣率
- 最终费率 = 折扣后费率 × (1 - 质押折扣率)

### 10.4 推荐人机制

#### 10.4.1 角色定义

| 角色     | 说明                                   |
| -------- | -------------------------------------- |
| 推荐人   | 邀请新用户的现有用户，可获得返佣       |
| 被推荐人 | 通过推荐链接注册的新用户，享受费率优惠 |

#### 10.4.2 关键参数

- **被推荐人最低费率层**：被推荐人自动享受的最低费率层级
- **最高返佣比例**：推荐人可获得的最高返佣比例
- **30天单用户最高可归因量**：单个被推荐人每30天可计入推荐人返佣的最大交易量

#### 10.4.3 返佣计算

**可归因交易量 = 较小值(本次成交量, 30天上限 - 已归因量)**

**推荐人收益 = 可归因交易量 × 返佣比例 × 手续费率**

### 10.5 收入分成

#### 10.5.1 分成类型

| 类型           | 说明             | 来源        |
| -------------- | ---------------- | ----------- |
| 推荐人返佣     | 推荐人获得的返佣 | Taker手续费 |
| 市场映射者分成 | 市场映射者的收益 | 交易手续费  |
| 订单路由器分成 | 订单路由器的收益 | 交易手续费  |
| 无条件分成     | 固定比例分成     | 协议收入    |

#### 10.5.2 分配优先级

总手续费收入按以下顺序分配：

1. 市场映射者分成（如配置）
2. 订单路由器分成（如配置）
3. 推荐人返佣
4. 无条件分成
5. 剩余进入协议金库

### 10.6 业务流程示例

#### 示例：推荐人收益计算

**场景**：

- Alice是推荐人
- Bob是被推荐人（由Alice邀请）
- Bob 30天已归因交易量：800,000美元
- 30天单用户上限：1,000,000美元
- 返佣比例：15%

**Bob执行一笔交易**：

- 成交量：50,000美元
- Taker费率：0.05%
- Taker手续费：50,000 × 0.05% = 25美元

**第一步：计算可归因交易量**

- 剩余归因额度：1,000,000 - 800,000 = 200,000美元
- 本次成交量：50,000美元
- 可归因交易量 = 较小值(50,000, 200,000) = 50,000美元

**第二步：计算Alice收益**

- Alice收益 = 50,000 × 0.05% × 15% = 3.75美元
- 或者：Alice收益 = 25（手续费）× 15% = 3.75美元

**第三步：手续费分配**

- Bob支付：25美元
- Alice获得：3.75美元
- 协议收入：25 - 3.75 = 21.25美元
- Bob 30天归因量更新：850,000美元

**归因量达上限后**：

- Bob继续交易100,000美元
- 可归因交易量 = 较小值(100,000, 0) = 0
- Alice不再获得该笔交易的返佣

## 11. 交易奖励

### 11.1 概述

交易奖励模块激励用户在平台上进行交易，奖励以协议代币形式发放。

### 11.2 奖励参数

主要参数包括：

- **国库账户**：奖励代币的发放来源
- **奖励代币**：用于奖励的代币类型
- **费用乘数**：用于计算奖励份额的乘数（默认99%）

### 11.3 奖励机制

**奖励分配基于**：

1. 用户支付的交易手续费
2. 用户的交易量
3. 费用乘数调整

**奖励计算**： 用户奖励份额 = 交易手续费 × 费用乘数

### 11.4 业务流程示例

#### 示例：交易奖励计算

**配置**：

- 费用乘数：99%
- 奖励池每日分配：10,000代币

**用户交易**：

- Alice支付Taker手续费：100美元
- Bob支付Maker手续费：50美元
- Carol支付Taker手续费：150美元

**第一步：计算各用户奖励份额**

- Alice份额 = 100 × 99% = 99美元
- Bob份额 = 50 × 99% = 49.5美元
- Carol份额 = 150 × 99% = 148.5美元

**第二步：计算总份额**

- 总份额 = 99 + 49.5 + 148.5 = 297美元

**第三步：分配奖励**

- Alice奖励 = 10,000 × 99 ÷ 297 = 3,333.33代币
- Bob奖励 = 10,000 × 49.5 ÷ 297 = 1,666.67代币
- Carol奖励 = 10,000 × 148.5 ÷ 297 = 5,000代币

## 12. 协议Vault机制

### 12.1 概述

Megavault是协议的核心流动性池，用户可以存入资金获得股份，共享Vault的交易收益。

### 12.2 核心概念

#### 12.2.1 股份系统

| 概念         | 说明                            |
| ------------ | ------------------------------- |
| 总股份       | Vault所有股份的总和             |
| 用户股份     | 单个用户持有的股份数量          |
| 股份价值     | 单股价值 = Vault总资产 ÷ 总股份 |
| 用户资产价值 | 用户股份 × 股份价值             |

#### 12.2.2 股份解锁期

新存入的股份需要等待一定区块数才能提取，防止即时套利。

### 12.3 核心公式

#### 12.3.1 存款获得股份

**新股份 = 存款金额 × 总股份 ÷ Vault总资产**

特殊情况：

- 如果总股份为0（首次存款）：新股份 = 存款金额（1:1）

#### 12.3.2 提取金额计算

**提取金额 = 用户股份 × Vault总资产 ÷ 总股份**

#### 12.3.3 股份价值

**股份价值 = Vault总资产 ÷ 总股份**

### 12.4 Vault费率优先级

Vault在费率层中始终处于最高层：

- 享受最低的交易手续费
- 通常为Maker负费率（返佣）
- 提高Vault整体收益率

### 12.5 业务流程示例

#### 示例1：存入资金到Megavault

**初始状态**：

- Vault总资产：1,000,000美元
- 总股份：1,000,000股
- 单股价值：1.00美元

**Alice存入10,000美元**：

**第一步：计算新股份**

- 新股份 = 10,000 × 1,000,000 ÷ 1,000,000 = 10,000股

**第二步：更新状态**

- 总股份 = 1,000,000 + 10,000 = 1,010,000股
- Vault总资产 = 1,000,000 + 10,000 = 1,010,000美元
- Alice股份 = 10,000股

**第三步：验证**

- 单股价值 = 1,010,000 ÷ 1,010,000 = 1.00美元（不变）
- Alice资产价值 = 10,000 × 1.00 = 10,000美元 ✓

#### 示例2：Vault盈利后提取

**场景**：Vault通过做市获利10%

**初始状态（Alice存款后）**：

- Vault总资产：1,010,000美元
- 总股份：1,010,000股
- Alice股份：10,000股
- 单股价值：1.00美元

**Vault盈利后**：

- Vault总资产：1,111,000美元（增长10%）
- 总股份：1,010,000股（不变）
- 新单股价值：1,111,000 ÷ 1,010,000 = 1.10美元

**Alice提取全部股份**：

**第一步：计算提取金额**

- 提取金额 = 10,000 × 1,111,000 ÷ 1,010,000 = 11,000美元

**第二步：更新状态**

- 总股份 = 1,010,000 - 10,000 = 1,000,000股
- Vault总资产 = 1,111,000 - 11,000 = 1,100,000美元
- Alice股份 = 0

**第三步：收益计算**

- Alice收益 = 11,000 - 10,000 = 1,000美元（10%）
- 与Vault整体收益率一致 ✓

#### 示例3：Vault亏损场景

**场景**：Vault亏损5%

**初始状态**：

- Vault总资产：1,000,000美元
- 总股份：1,000,000股
- Bob股份：100,000股（10%份额）
- Bob资产价值：100,000美元

**Vault亏损后**：

- Vault总资产：950,000美元（亏损5%）
- 总股份：1,000,000股（不变）
- 新单股价值：0.95美元
- Bob资产价值：100,000 × 0.95 = 95,000美元

**Bob提取**：

- 提取金额 = 100,000 × 950,000 ÷ 1,000,000 = 95,000美元
- Bob亏损：100,000 - 95,000 = 5,000美元（5%）

**结论**：

- 用户与Vault共享盈亏
- 股份数量不变，股份价值变化
- 风险与收益按比例分配

## 附录：核心公式汇总

### A. 账户与保证金

| 公式                                                       | 说明                   |
| ---------------------------------------------------------- | ---------------------- |
| 净抵押品 = 资产价值 + 仓位净值                             | 账户实际净资产         |
| 初始保证金 = 名义价值 × 调整后保证金率                     | 开仓所需最低保证金     |
| 维持保证金 = 初始保证金 × 维持比例                         | 维持仓位所需最低保证金 |
| OIMF调整 = 基础保证金率 + 缩放因子 × (100% - 基础保证金率) | 动态保证金率调整       |

### B. 价格与交易

| 公式                            | 说明         |
| ------------------------------- | ------------ |
| 实际价格 = 存储值 × 10^指数     | 价格换算     |
| 报价量 = 数量 × 价格 × 转换系数 | 成交金额计算 |
| 手续费 = 报价量 × 费率          | 手续费计算   |

### C. 资金费率

| 公式                                             | 说明         |
| ------------------------------------------------ | ------------ |
| 溢价 = 影响价格 ÷ 指数价格 - 1                   | 溢价计算     |
| 资金费率 = 钳制(平均溢价 + 默认费率, 最大钳制值) | 资金费率计算 |
| 资金费支付 = 仓位 × (当前索引 - 上次索引)        | 资金费结算   |

### D. 清算

| 公式                                 | 说明               |
| ------------------------------------ | ------------------ |
| 破产价 = 债务 ÷ 仓位大小             | 破产价计算（多头） |
| 可成交价 = 破产价 × (1 ± 价差率)     | 清算订单价格       |
| 保险基金变化 = 成交金额 - 破产价金额 | 保险基金盈亏       |

### E. Vault

| 公式                              | 说明         |
| --------------------------------- | ------------ |
| 新股份 = 存款 × 总股份 ÷ 总资产   | 存款获得股份 |
| 提取金额 = 股份 × 总资产 ÷ 总股份 | 提取金额计算 |
| 股份价值 = 总资产 ÷ 总股份        | 单股价值     |
